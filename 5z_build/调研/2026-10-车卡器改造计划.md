# 5z 车卡器改造计划（2026-10）

> 依据：`2026-10-5z车卡器竞品调研与功能对比.md`（现状实测 + 竞品对比 + 差距分析）
> 目标：把车卡器从「懂规则才敢用的编辑器」改成「新手能走通、老手能快、数值可信」，分 6 批发布，每批可独立上线/回滚。
> 约束：纯静态、零前端框架、零依赖；不重写框架、不引入后端/账号；不改规则书正文；Word 导出骨架不动（只补字段）。

---

## 0. 总体策略

| 原则 | 说明 |
|---|---|
| **先交互后自动化** | 先解决「找不到/不敢点/刷新丢」；再做装备、升级等规则自动化 |
| **小步发布** | 每批 1–2 天，独立构建/验证/上线，群友可即时反馈；避免一次大改 |
| **复用已有资产** | `picker.js`（分页/筛选/详情）、`card-data`（数据同源）、`fflate`（分享/压缩）、现有 Word/Excel 导出 |
| **数据只增不改** | 优先给 `parse-card-data.mjs` 加结构化字段；解析不可靠时运行时解析 + 手填兜底 + 显示来源标记 |
| **严格/自由双档** | 校验默认提示、可开关；导出前强校验。房规/私设不被硬卡死 |
| **每批可回归** | 断言脚本 + 截图对比 + Word/Excel 打开验证 + 线上 CDP 复测 + changelog 记录 |

**改动文件范围（固定）**

| 文件 | 用途 |
|---|---|
| `5z_build/assets/car.js` | 车卡器主逻辑（2594 行，主要改动面） |
| `5z_build/assets/car.css` | 布局/移动端 |
| `5z_build/assets/picker.js` / `picker.css` | 专长页复用；如需小扩展（如「可选/不可选」态） |
| `5z_build/car.html` | 步骤条/头部/布局微调（构建模板） |
| `5z_build/parse-card-data.mjs` | 种族属性加值、装备、职业表的**结构化字段**（只在需要时改） |
| `5z_build/changelog.json` | 每批发布记录（`node 5z_build/gen-changelog.mjs` 重生成更新日志页） |

**本地闭环（每批都跑）**

```powershell
# 1) 改源码
# 2) 构建 + 同步
node 5z_build/build.mjs
node 5z_build/sync-web.mjs
# 3) 本地起服务 + 回归
node 5z_build/_test-serve.mjs . 8765
node 5z_build/_test-car-regression.mjs http://127.0.0.1:8765/car
# 4) 导出回归
node 5z_build/_test-docx-export.mjs
node 5z_build/_test-xlsx-export.mjs
# 5) 发布（构建+检查+同步，不提交）
node 5z_build/update.mjs --no-extract --dry-run
# 6) 提交/推送 → Pages/Cloudflare 上线 → 线上 CDP 复测
```

## 1. 阶段 0：基线与回归（0.5 天）

**交付**

1. `5z_build/_test-car-regression.mjs`（gitignored）：把本次实测断言化，覆盖：
   - 专长页 DOM 条目数 ≤ 80、页面高 < 9,000px
   - 未选种族点「下一步」被拦截或有明确提示
   - 第 11 步刷新后仍停在第 11 步
   - 1 级角色选 2 环法术被拦/警告
   - 390×844 下无横向溢出、实时预览可见
   - 导出按钮在必填缺失时给出问题清单
   - 桌面/移动关键页截图存档（对比用）
2. 基线快照：当前 18 张截图 + `report.json` 归档到 `5z_build/_shots/car-audit/baseline/`
3. 数据体检脚本 `_scan-card-data.mjs`（一次性）：统计种族「属性值加成」可解析比例、专长「先决条件」写法分布、职业表法术列写法，决定 P0-5 的实现方式（结构化 vs 运行时解析）。

**验收**：回归脚本可在本地 1 分钟内跑完并全部给出 PASS/FAIL；基线数据入库（本地）。

## 2. 批次 A：快速止血（1 天）→ 立刻发布

**A1 恢复 bug（0.5 小时）**
- `car.js:126` `Math.min(7, …)` → `Math.min(11, …)`；加载时 toast「已恢复上次进度（第 N 步）」。
- 验收：任意步骤刷新停原步；旧档兼容。

**A2 专长页 Picker 化（0.5–1 天）**
- `renderFeats()` 改用 `Picker.create`：分页 60–80、分类 chips（7 类）、搜索、已选面板吸顶、先决条件单独一行 + 「仅显示当前可选」过滤。
- 默认排序：1 级可选/职业相关优先；保留「额外专长数量」输入。
- 验收：DOM ≤80；页面高 <9,000px；已选面板始终可见；「选择/移除」回归通过。

**发布**：批次 A 单独发一版（changelog 1 条），线上复测 + 群内可观察。

## 3. 批次 B：不迷路 + 不返工（2 天）→ 发布

**B1 步骤守卫 / 完成度 / 待补清单（1 天）**
- 每步定义必填/选填：种族、职业、属性合法、技能满额、专长满额、法术满额（施法者）、战技/程序（视职业）、购物（选填）。
- 步骤条状态：`必填未完成(!)` / `已完成(✓)` / `选填`，不再用「序号在前」冒充完成。
- 「下一步」在必填未完成时：高亮缺失项 + 提示 + 「仍要继续（自由模式）」二次确认。
- 角色卡步新增「待补清单」，可点击跳转到对应步骤。
- 验收：未选种族不能静默前进；完成度与真实状态一致；导出前弹出待补清单。

**B2 校验引擎 + 问题面板（1 天）**
- 新增 `validateAll()`：返回 `[{level, step, message, fix}]`，覆盖：
  - 法术：按职业表「已知戏法/已知法术/法术位」配额；准备上限；环阶不得超过当前等级可获得的最高环
  - 专长：配额；可解析的先决条件（属性值、等级、职业/种族名）
  - 技能：配额 + 职业可选池（软提示）
  - 战技：流派入门专长提示（先软提示）
  - 购物：预算超支
- UI：顶部「问题(n)」按钮 + 面板，点击定位到步骤；错误红 / 警告黄；「一键修正」（如自动去掉超选的法术）。
- 「下一步」与导出复用同一校验结果；自由模式只提示不拦。
- 验收：1 级选 2 环法术被拦/警告；超选法术有明确文案；导出前强校验；问题可定位。

## 4. 批次 C：把规则算给玩家（2 天）→ 发布

**C1 种族属性加值自动化（1 天）**
- 数据侧：优先在 `parse-card-data.mjs` 给 `races[].traits` 输出结构化 `abilityBonuses`（解析「属性值加成：你的感知+2，敏捷+1」等写法；解析失败保留原文并标记 `manual`）。
- 前端：`finalAttr = base + manual + levelUp + racialBonus`；属性卡片显示「基础 8 + 种族 2 + 升级 1 = 11」，点 `?` 看算式；「手动调整」改名「额外加值（专长/物品等）」并折叠。
- 种族训练/亚种带来的技能熟练自动写入技能步（可取消）。
- 验收：选被遗忘者后感知 +2/敏捷 +1 自动生效；数字可展开算式；未解析的种族显示「需手填」徽标。

**C2 点购/标准组硬约束 + 随机（0.5–1 天）**
- 点购模式：单项 8–16、总点 ≤32，超限即时提示且不允许下一步；标准组选择后锁定基线（可微调但提示来源）。
- 「随机掷骰」支持只重掷单项/全部；「留空即随机」为后续快速模式预留。
- 验收：购点不能超 32；规则文案与实际约束一致。

## 5. 批次 D：移动端可用（1 天）→ 发布

- 头部压缩：标题+版本一行；导出/导入/新建收进「⋯」菜单；测试版横幅默认折叠（可点开）。
- 步骤条横向滚动（不换 3 行）。
- `#live` 改为底部浮动摘要（当前步相关 4–6 个数值）+ 可展开抽屉；桌面保持右侧栏。
- 角色卡宽表：小屏卡片化（或容器横向滚动 + 首列固定）。
- 验收：390×844 首屏可见步骤内容；实时数值始终可见；无横向溢出；桌面无回归。

## 6. 批次 E：装备与 AC/攻击（3–4 天）→ 发布（P1 核心）

**E1 常规装备数据接入（1–2 天）**
- `parse-card-data.mjs` 新增常规装备（武器/护甲/盾/法器/冒险用品）解析 → `assets/card-data/equipment.json`（名称/价格/伤害/AC/属性/重量/分类）。
- 数据源：规则书「装备/常规物品」页面（构建时自动解析，保持与规则书同步）。

**E2 起始装备与购物（1 天）**
- 职业起始装备包 A/B（逐行选择，参照 DND 车卡大师的「逐行 A/B」）、起始金币；DM 额外金币可选。
- 购物步合并「常规装备 + 魔法物品」；已购清单可改数量；预算自动默认 = 起始金币。
- 验收：选职业后能一键领装备包；金币自动算；已购清单进角色卡与 Word。

**E3 装备→AC/攻击自动（1 天）**
- `armorType/shield/armorBonus` 补 UI 与自动推导；武器自动生成攻击表（命中/伤害/射程/属性），写入角色卡与 Word。
- 验收：穿甲/持盾后 AC 与来源更新；角色卡出现武器攻击表；Word 同步。

## 9. 发布流程（每批固定）

| 步骤 | 命令/动作 | 通过标准 |
|---|---|---|
| 1 本地构建 | `node 5z_build/build.mjs` | 无报错，card-data 解析通过 |
| 2 完整性检查 | `node 5z_build/check-links.mjs`、`node 5z_build/verify-complete.mjs` | 全绿 |
| 3 同步 | `node 5z_build/sync-web.mjs` | 根目录产物更新 |
| 4 回归 | `_test-car-regression.mjs` + `_test-docx-export.mjs` + `_test-xlsx-export.mjs` | 全 PASS；Word/Excel 可打开 |
| 5 人工走查 | 本地 serve：桌面 1440 + 移动 390 各走一遍完整建卡 | 无阻断问题 |
| 6 提交 | `git commit`（`feat(car): ...` / `fix(car): ...`） | 仅含预期文件 |
| 7 发布 | push（Pages + Cloudflare 自动） | 线上 `car` 可访问 |
| 8 线上复测 | `_test-car-regression.mjs https://5z-rules.top/car` | 全 PASS |
| 9 记录 | changelog entry → `node 5z_build/gen-changelog.mjs`；知识库记一条经验 | 更新日志页可见 |

**回滚**：每批一个 commit，出问题 `git revert <sha>` 重发；存档新增字段必须向后兼容（旧 localStorage / 旧 JSON 可读）。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 规则文本解析不可靠（种族加值/先决条件/职业表） | 先跑 `_scan-card-data.mjs` 统计；能解析才自动化，否则保留手填 + 「需手填」标记；绝不静默算错 |
| 校验误伤房规/私设 | 严格/自由开关；默认软提示；导出前可确认忽略；问题面板可逐条跳转 |
| 移动端 CSS 影响桌面 | 媒体查询隔离 + 桌面/移动截图对比回归 |
| Word/Excel 导出回归 | 复用现有导出测试 + Word COM 打开验证；每批跑 |
| 存档格式变更 | 加 `version`/`rulesVersion` + 迁移函数；用旧档做兼容测试 |
| 4.5MB card-data 首屏 | 本轮不动；P1 可评估按步骤懒加载（收益有限，谨慎） |
| 改动面大、回归漏 | 每批小范围 + 断言脚本 + 线上复测；保留基线截图 |

## 12. 需要你拍板的 4 件事

1. **本轮范围**：
   - A（推荐）：批次 A+B+C（专长页、守卫生效、校验、种族/属性自动化），约 3–4 个工作日，一次明显变好；
   - B：只做 A+B（约 2 天，最快见效）；
   - C：A+B+C+D+E（含移动端与装备，约 6–8 天）；
   - D：先只出每个批次的详细技术设计，不改代码。
2. **校验默认档位**：默认「提示不拦」（自由）还是「必填未完成不能走」（严格）？建议默认严格、可切换。
3. **发布节奏**：每批立即上线 vs 攒 2–3 批一起发？建议每批上线（群友可反馈）。
4. **数据解析授权**：允许改 `parse-card-data.mjs`（种族加值/装备/职业表结构化）吗？这会动构建产物，但能让自动化真正落地；不允许则降级为「运行时解析 + 手填兜底」。
