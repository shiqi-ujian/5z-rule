## ① 调研方法

### 1.1 检索与核实流程

1. **先定位每个工具的官方入口**（官网 / 帮助中心 / GitHub / 应用商店 / 官方论坛），逐一 `web_fetch`；
2. 官方页面能拿到的信息记为**一手证据**；拿不到的（反爬、Cloudflare、JS 单页应用只吐空壳），转而用**官方帮助中心文章标题、官方论坛员工回复、厂商对比页、行业榜单、社区帖子**做二手互证；
3. 对"用户评价"这一项，优先找**带日期的论坛帖 / 榜单评测**（Reddit 在本次环境不可达，见 1.2）；
4. 每个工具标注 **证据强度**：
   - **A**＝我直接抓取到官方页面正文；
   - **B**＝二手来源＋官方页面存在性可确认；
   - **C**＝**未核实**，仅记录线索，不可当事实引用。

## ② 逐个工具

### 1. D&D Beyond Character Builder（官方，赛道基准）

**证据强度：B**（帮助中心 Master Tier 页 A；车卡器本体页面全部被拦）

- **入口**：<https://www.dndbeyond.com/characters/builder>（正文抓取失败）；帮助中心 <https://dndbeyond-support.wizards.com/hc/en-us/articles/7747238580500-Master-Tier>（抓取成功，页面标注 *Updated May 12, 2026*）
- **定位 / 收费**：WotC 官方授权的"内容商店 + 车卡器 + 数字卡 + VTT"综合体。账号免费但**免费账号最多 6 个角色**、最多 6 个 encounter（Master 页原文），角色/遭遇无限、去广告、订阅者内容库、内容共享、Maps/Sigil 权限都在付费层。价位二手来源一致为 **Hero ≈ \$2.99/月、Master ≈ \$5.99/月**（[StartPlaying](https://startplaying.games/blog/posts/every-character-maker-dnd) 写"GM tiers at \$2.99 and \$5.99/month"；[The Endlessness 榜单](https://theendlessness.com/blog/best-dnd-apps) 写"\$5.99/mo for full features"）——**官方价目页未抓取成功，标【二手】**。官方书要**单独买**，数字书与实体书不互通，这是社区最常骂的点。
- **交互模型**：**双轨**。① **QuickStart**：几分钟生成 1 级角色，只问最关键的几个选择；② **Standard 分步向导**：逐步走完并带新手教程文案；③ 另有**预生成角色**直接取用（三条均见 [StartPlaying 2025-04 榜单](https://startplaying.games/blog/posts/every-character-maker-dnd)）。选完即写入右侧/后续的角色卡，"digital character sheet auto-calculates everything"（[The Endlessness](https://theendlessness.com/blog/best-dnd-apps)）。
  官方帮助中心还单列了 `Character Creation Methods`、`Builder Sections`、`Character Header`、`Sheet Sections` 等文章（搜索引擎结果确认存在，正文 403）：说明其**向导被拆成可跳转的 section 组**，而非一条不可回退的直线。
- **自动化程度**：全派生值自动（属性/技能/HP/AC/先攻/熟练/法术位/装备加值）；多职业、专长前置、法术数量校验由规则引擎拦截（**具体拦截文案与边界未核实**）。升级时按职业表逐级给出选项（此为 DDB 核心卖点，但本次未抓到官方页面，标【未核实】）。
- **内容与扩展性**：官方全量（买即解锁）；**Subscriber Content Library 每周/每月随 D&D Beyond Drops 增长**（Master 页原文）；社区 homebrew 的魔法物品/法术/怪物可加入个人 Homebrew Collection 后用于角色（Master 页原文）。**Homebrew 建卡器覆盖 background / feat / magic item / monster / species / spell / subclass，但没有"基础职业"编辑器**——这条来自 [Fantasy Grounds 的对比页](https://www.fantasygrounds.com/compare/dnd-beyond/)（2026-09 复核；注意 SmiteWorks 是竞品，有立场，但与社区长期抱怨一致）。
- **产出**：网页角色卡；**原生 PDF 导出未核实**（通常靠浏览器打印）；分享靠 **Campaign Content Sharing（Master 最多 5 个 campaign）**；卡可直接进 **Maps**（2D VTT）与 **Sigil**（3D VTT，Master 可开 15 局）（均 Master 页原文）。
- **存档与协作**：账号云存档（原文 "Account-based cloud library and browser service"）；DM 可共享内容库给全队；有 `Digital Source Books Offline` 这条帮助文章（离线读电子书，正文未核实）。
- **移动端 / 离线**：iOS/Android 官方 App（多份榜单一致）；离线仅限"已购电子书"层面。
- **真实评价**：
  - 优点：官方内容、UI 好、适合整队使用（[The Endlessness](https://theendlessness.com/blog/best-dnd-apps)）。
  - 抱怨 ①"**信息过载**，角色卡在线和打印都**难读难导航**"（[StartPlaying](https://startplaying.games/blog/posts/every-character-maker-dnd) 原文 "the character sheet output is difficult to navigate both online and in print"）；抱怨 ② 电子书另买"stings"、homebrew 有限（The Endlessness）；抱怨 ③ 有用户直言"用起来令人沮丧，具体原因我都说不清"（[feddit/Lemmy 讨论](https://feddit.fr/post/23102)）。
- **可被我们借鉴（1-3 条）**
  1. **QuickStart / Standard 双入口**：我们 11 步向导可以加一个"3 步极速模式（种族→职业→属性随推荐，其余后补）"，把"想快点开打"的用户从 11 步里解放出来。
  2. **把向导 section 化、可跳转可回退**：DDB 把"角色头部 / 卡面区块 / 创建方式"拆成独立 section，用户永远知道自己在哪、能跳哪。我们 11 步应显式给出"步骤地图 + 已完成/待补"状态。
  3. **订阅者内容库式"每周新增"节奏**：我们有 1196 法术 / 804 专长，可以在站点上做"本周新增/最近修订"位，让内容量变成可见的持续价值，而不是一次性堆料。

### 2. Roll20 Charactermancer（+ 新的 Roll20 Characters）

**证据强度：A（营销子站正文）＋ B（帮助中心/应用页 403）**

- **入口**：官方指南 <https://pages.roll20.net/dnd/character-creator-guide>（抓取成功，2024-03-05）；实际车卡器 <https://app.roll20.net/characters/create/dnd2024byroll20>（403）；旧 5e 入口 `/characters/create/dnd5e`。
- **定位 / 收费**：免费 VTT + 内容购买；**不需要进游戏就能独立建卡**（"Roll20 Characters"网页版，Demiplane 员工在官方论坛把它当作自家缺失车卡的替代品推荐：<https://forums.demiplane.com/t/wait-i-cannot-create-dnd-characters/5778>）。Roll20 订阅价二手为 \$7.49 / \$13.99 每月（[The Endlessness](https://theendlessness.com/blog/best-dnd-apps)）【二手】。
- **交互模型**：**标准 7 步向导**，顺序明确写在官方指南里：
  **① 种族 → ② 职业 → ③ 属性（点数分配或虚拟掷骰，实时显示加值影响）→ ④ 背景 → ⑤ 装备 → ⑥ 法术 → ⑦ 专长**。
  官方原话的三个关键设计：
  - "each screen offers insights into 5e rules"（**每屏内联规则解释**）；
  - "populates their choices directly onto the sheet… **select different ones to compare**"（**边选边写入卡，可反复换选对比**）；
  - 另有 **NPC 生成器**（按 CR 预置属性数组，秒出卫兵/法师）与 **直接改卡**（"direct sheet editing for advanced control"）。
- **自动化程度**：向导内**按 5e 规则校验**（"automatically validate choices under 5E rules"），并自动算攻击加值、豁免 DC、HP 等派生值；**一旦切到直接改卡就没有校验**——官方自己写明"without the validation checks… mistakes or exploitative min-maxing builds are possible"。多职业/专长前置：直接改卡路径可做"任意兼职"，但**失去校验**；向导路径的兼职支持程度【未核实】。
- **内容与扩展性**：2014 与 2024 两套基础规则免费，其余按书购买（[StartPlaying](https://startplaying.games/blog/posts/every-character-maker-dnd)）；自制内容靠 VTT 内手改卡，没有 DDB 那种 homebrew 建卡器（**未核实**是否有等价物）。
- **产出**：网页卡进 VTT；**StartPlaying 明确写"没有打印角色卡选项"**（"No option to print the character sheet"）【二手，但是目前唯一可得的明确说法】。分享靠 VTT 房间/角色归属。
- **存档与协作**：账号云存档；DM 在房间内看全队卡。**痛点**：Demiplane 论坛用户 2025-12 原话——"roll20 experience is not great… **difficult to update and level unless you on the tabletop with a session**"（<https://forums.demiplane.com/t/wait-i-cannot-create-dnd-characters/5778>）。即"能建卡，但日常升级仍被绑在会话流程里"。
- **移动端 / 离线**：浏览器（移动端可用性【未核实】）；无离线。
- **真实评价**：StartPlaying 给"简单直观、对新手友好、有教程"，同时列"**某些选择令人困惑或缺失**（例：背景属性加值提示要选，却没给出可选方式）"、"不能打印"。Demiplane 论坛那条差评是"脱离桌面就难升级"。
- **可被我们借鉴**
  1. **每步内联规则解释 + "选择即可对比"**：我们把 11 步里每一步做成"选 A 立刻看到卡面变化，选 B 再对比"，直接对治"相当难用"里的"我不知道我在选什么"。
  2. **降级路径要显式**：Roll20 的"向导有校验 / 手改无校验"是清晰的两档心智。我们可以给"严格模式（校验战技/程序/法术数量）"和"自由模式（只提示不拦）"两个开关。
  3. **NPC/怪物速成器**：我们已有 679 怪物数据，做一个"按 CR 秒出 NPC 卡"的旁路，成本低、复用高。

### 3. Foundry VTT 的 dnd5e 系统 + D&D Beyond Importer / Plutonium（进阶自动化参照）

**证据强度：A**（三处官方/仓库页面均抓取成功）

- **入口**：系统页 <https://foundryvtt.com/packages/dnd5e>；购买页 <https://foundryvtt.com/purchase/>；DDB Importer <https://github.com/MrPrimate/ddb-importer>；Plutonium <https://5e.tools/plutonium.html>
- **定位 / 收费**：Foundry 本体 **\$50 一次性买断、永久许可、含后续更新**（购买页原文，页面还按当日汇率显示约 ¥347）；`dnd5e` 系统**免费**（代码 MIT）；官方 D&D 模块（PHB 2024 / DMG 2024 / MM 2024 / Tasha / 冒险）**另买**。
- **交互模型**：**卡片内自由编辑**，不是向导；但 dnd5e 官方把 **"automatic character advancement"** 列为核心特性之一（系统页原文）——即**升级时由系统弹出该等级要做的选择**（职业特性/属性提升/法术），选择后自动落到卡上。另有拖拽建卡、Character Wizard 类模块（社区）。
- **自动化程度**：本清单里**最高**。系统页列出的能力包括：Party actor（组队后 XP/金币/战利品分配、群体豁免与被动检定对比）、Requested Rolls（DM 指定 DC 要求掷骰）、Ruletips（规则名词悬浮解释）、Item Containers（容器/背包）、Expanded Automation、vision modes。第三方加装：
  - **DDB Importer**：把 DDB 角色**导入并回写同步**（回写为 Patreon 权益），导入法术/物品/怪物；需要填 DDB 的 `CobaltSession` cookie（README 明示"把 cookie 给别人等于交出密码"，并提供自建代理方案）。
  - **Plutonium**：从 5e.tools 导入职业/子职/背景/种族/专长/怪物/法术/物品/冒险/表格，**也支持 homebrew 仓库、UA 预发布仓库、URL 与文件上传**；配 Rivet 浏览器扩展可"5e.tools 一键送到 Foundry"。
- **内容与扩展性**：SRD 5.1 + SRD 5.2（系统页 License 段确认）+ 官方付费模块 + 5e.tools 全量 + 社区 homebrew 仓库 + Forge 社区市场。**扩展性天花板＝"能写 JS 就能加规则"**。
- **产出**：没有"打印一张卡"的强概念（靠模块）；导出以 actor JSON / 模块打包为主；分享靠世界/模块。
- **存档与协作**：**自托管**（本机或服务器）世界文件；官方无云存档（The Forge 等第三方托管另付费）；多人＝同桌进同一个世界，天然"DM 查看全队"。
- **移动端 / 离线**：浏览器访问，触屏体验一般（**未核实**）；离线＝本机服务可用。
- **真实评价**：The Endlessness 榜单评价"一次性买断 + 模块生态无敌"，缺点"需要自托管、**setup isn't trivial**、要折腾"。DDB Importer 的 cookie 机制本身就是安全与门槛的双重成本（README 自陈）。
- **可被我们借鉴**
  1. **"advancement" 思维**：升级不是"重填一遍表"，而是"系统只问这一级新增的选择"。我们的战技/程序/灵能师升级完全可以用同一套"增量提问"。
  2. **Import/Export 生态位**：Plutonium 支持"URL / 文件 / 仓库"三种内容源——我们的 JSON 导入可以升级为"**可分享的内容包 URL**"（一行链接导入一套自制战技），这是纯静态站也能做到的。
  3. **Ruletips**：卡面上每个专有名词（战技、程序、灵能点）悬浮出 100 字解释。零后端，收益极大。

### 4. MPMB's Character Record Sheet（自动化可填写 PDF）

**证据强度：A**（官网首页 + FAQ 全文抓取成功）

- **入口**：<https://www.flapkan.com/>、FAQ <https://www.flapkan.com/faq>、GitHub <https://github.com/morepurplemorebetter/MPMBs-Character-Record-Sheet>
- **定位 / 收费**：**"Pay What You Want"** 的 PDF 车卡器（FAQ 原文）；**2024 规则（5.5e）版本目前是 beta，仅 Patreon 订阅者可取**；"完整法术表 / 冒险日志"等附加 PDF 也是 Patreon 权益。当前稳定版 **v14.1.2（2014 规则）/ v24.1.2（2024 规则）**。
- **交互模型**：**不是分步向导，而是"填表 + 自动化"**。官方描述："Set race, background, abilities, class, level, and let the sheet do the rest"——先设种族/背景/属性/职业/等级，其余自动派生；交互发生在 PDF 对话框里，可来回改。
- **自动化程度**：极高且细：装备/魔法物品加值、替代职业特性、专长附赠法术、法术表一键生成（含种族/专长/魔法物品/灵能来源）、荒野形态数值、伙伴/召唤物、公制单位切换。**"法术选择数量校验"未核实**。
- **内容与扩展性**：**只有 SRD 内容**，官方 FAQ 明说原因："sheets only contain the materials that are in the SRD… not licensed by Wizards"，且"拿授权就不免费了"。扩展靠 **import script**（社区 Add-on Script Index + /r/mpmb + Discord）。
- **产出**：**本身就是可打印纸卡**（"optimized for printed use at the table"，无广告无订阅无联网）；`Flatten` 按钮生成"只读版"给 DM 或平板看。
- **存档与协作**：**本地 PDF 文件**就是存档；换版本要手动走 Import 流程，且 FAQ 承认**跨大版本会丢内容**（v12.998 → v13 起只带 SRD，需先装 import script）；给 DM 看要 print-to-PDF。
- **移动端 / 离线**：**硬限制**——只在 **Windows/macOS 的 Adobe Acrobat DC** 上工作（用的是 Acrobat JavaScript API）；**移动端 Acrobat 不支持**；Mac 上**绝不能用 Preview 打开**（会剥掉 JS 并自动保存，文件可能报废）。离线可用。
- **真实评价**：FAQ 本身几乎就是"用户抱怨合集"：为什么选项不全（SRD 限制）、为什么打不开（Acrobat 限制）、为什么发给 DM 看不到、为什么没有中文（**英文唯一版本**）、为什么没有暗色模式。社区侧口碑是"自动化最强、最像真纸卡"。
- **可被我们借鉴**
  1. **Flatten / 只读快照**：一键导出"不可编辑的展示版"（图片或只读 HTML）发给 DM，比让对方也打开我们的工具更现实。我们已有 Word/Excel 导出，可再加"只读网页快照 + 短链"。

### 6. Fast Character（快速预生成）

**证据强度：A**（官网首页完整抓取，含全部下拉项）

- **入口**：<https://fastcharacter.com/>（2024 规则版）；旧版 <https://fastcharacter.com/index2014.htm>
- **定位 / 收费**：**免费**，Patreon 赞助 + 页面广告位（首页有 Patreon 按钮与"Buy us a coffee"）；无账号、无后端。
- **交互模型**：**一张超长表单，一次成型**，没有分步：
  玩家名 / 战役或玩家 ID → 职业（含子职业，且 Fighter 等按 STR/DEX 分版本）→ 等级 1-20 → 种族（2024 物种 + 一大票 legacy 种族 + 自制种族）→ 背景（"match to fit Class"是个很聪明的选项）→ 是否包含 Ideal/Bond/Flaw → 属性生成方式（标准数组 / 4d6 弃最低 / 3d6 / 27 点购，**并把常见点数组合直接列成选项**）→ 装备/外貌/语言/种族特性覆盖 → 生成。
  **核心交互信条写在页面上**："Note: Any below option left blank will be **randomly** set."（**留空即随机**）
- **自动化程度**：生成即全部算完（属性、HP、AC、技能、法术、装备、特性、背景叙事），输出是一张完整卡；但**选择粒度换速度**：部分组合被自动决定（StartPlaying 抱怨"some choices made automatically"）。**多职业：不支持（未核实到兼职入口）**；法术数量校验：由生成器内部保证，用户不参与挑选。
- **内容与扩展性**：PHB 2024 全职业/子职/物种/背景 + 2014 legacy + 一批明确标注 `-- UNOFFICIAL HOMEBREWS --` 的种族（Android、Bariaur、Brownie、Deva…）。**不能导入自己的内容**。
- **产出**：可打印的网页角色卡（含规则速查 crib sheet）；StartPlaying 称"allows exports to Roll20 and other formats"（**官网未核实到 Roll20 导出入口**）。
- **存档与协作**：**无账号**；表单里有 `Campaign or Player ID` 字段，推测用于把角色归组（**机制未核实**）。
- **移动端 / 离线**：纯 HTML 表单，移动浏览器可用；无离线包。
- **真实评价**：优点"几秒钟出角色、支持多系统（B/X、Cypher、Marvel）、适合带新人/跑展会"；缺点"**广告扰人**、自动决定太多、定制空间小"（[StartPlaying](https://startplaying.games/blog/posts/every-character-maker-dnd)）。
- **可被我们借鉴**
  1. **"留空即随机"**：一行提示 + 一个"随机填充剩余项"按钮，能把 11 步的压迫感瞬间降到 1 步。
  2. **属性生成直接列组合**：它把 27 点购的常见分配列成下拉项，用户不用算。我们的属性步可以照抄这个"预置数组 + 手调"两层结构。
  3. **它证明了纯静态、无账号、单页能做出可用的车卡器**——这是对我们可行性最直接的证据。

### 8. Dicecloud（开源网页角色卡）

**证据强度：A（README + GitHub API）**

- **入口**：<https://dicecloud.com/>（JS 空壳）；源码 <https://github.com/ThaumRystra/DiceCloud>；README 原文抓取成功

- **自动化程度**：**"可审计"是它的核心**：每个数字都能追到来源；示例是"脱下 +1 体质板甲 → 潜行劣势消失、AC 变、速度变、体质变、进而 HP 与体质豁免变"，拖一下装备全部重算。**多职业/专长前置/法术数量校验：未核实**（自由编辑模式下大概率不强制）。
- **内容与扩展性**：SRD + 手工录入 homebrew；被公认为"homebrew 支持最好"（[The Endlessness](https://theendlessness.com/blog/best-dnd-apps)："handles homebrew better than anything else on the market"）。
- **产出**：网页卡；**实时协作**（README："free, auditable, real-time character sheet"）；分享靠链接/库。
- **存档与协作**：账号云（Meteor 后端）；也可自托管完全离线。
- **移动端 / 离线**：浏览器；自托管可离线。
- **真实评价**：优点"极灵活、免费、homebrew 最强"；缺点"**学习曲线像悬崖**（learning curve shaped like a cliff）、UI 该打磨"（The Endlessness）；README 自己承认"设置更慢"。
- **可被我们借鉴**
  1. **可审计数值**：点开 HP 旁边的 `?`，列出"基础 8 + 体质 2×3 + 专长 4 + 装备 2"的算式。这是对"难用/不透明"最便宜的解药，纯前端可做。
  2. **拖拽即重算**：我们在"购物"步之后的装备变更，也应该触发全卡重算（而不是让用户回去改）。
  3. 它的失败教训：**"更灵活"不等于"更好用"**。我们不必追求 Dicecloud 式自由编辑，向导 + 局部自由编辑更合适。

## ③ 2025–2026 赛道趋势

### 3.1 规则底座换代：2024 规则（5.5e / SRD 5.2）已成默认

- Fast Character **默认页就是 PHB 2024**，2014 版被降级为"HEY! WHERE'S THE OLD VERSION?"链接（<https://fastcharacter.com/>）；
- Foundry `dnd5e` 系统 License 段同时引 **SRD 5.1 与 SRD 5.2**，官方商店已上 PHB/DMG/MM 2024 模块（<https://foundryvtt.com/packages/dnd5e>）；
- MPMB 已有 **v24.1.2（2024 规则）**，但**锁在 Patreon 后面**（<https://www.flapkan.com/faq>）；
- Roll20 2024 卡入口就叫 `dnd2024byroll20`，且 Demiplane 官方新闻稿说"在 2024 发布前推出全新卡与建卡器"（<https://www.demiplane.com/blog/roll20-acquires-demiplane>，2024-06-04）；
- Demiplane 的 D&D Nexus 已售 2024 书（论坛用户 2025-11 提及）。

→ **含义**：新工具如果只支持 2014，会被视为"legacy"。我们是自制规则体系，反而不受此约束，但**"规则版本"必须显式标注**（我们已经有 1.49/1.50 这种版本号，应在车卡器里显示并写进导出文件）。

### 3.2 整合与停滞：Roll20 收购 Demiplane，5e 车卡难产

- Roll20 于 **2024-06-04** 宣布收购 Demiplane（<https://www.demiplane.com/blog/roll20-acquires-demiplane>），官方称"Demiplane 是 best-in-class character-building solution"，同时明确**5e 车卡由 Roll20 侧承接**；
- 结果：Demiplane 的 5e NEXUS 车卡从 "2H 2023" 一路延期到 **2026-07 仍无**，官方员工 2025-12 直接说"没有 5e 车卡器"（论坛证据见 §7）。
- **结论**：**"官方内容 + 好车卡"这个位置目前事实上只有 DDB 一个玩家**，第二名（Roll20/Demiplane 合并体）还在内部整合。这对我们是机会窗口：**在"非官方规则"这个细分里，没有强势玩家**。

### 3.3 DDB 从"车卡器"扩成"平台"

Master Tier 页（2026-05 更新）已经把权益写成：内容共享（5 个 campaign）、**Maps VTT**（可上传自制/动态地图，10GB）、**3D Sigil VTT**（可开 15 局）、Encounters 工具、订阅者内容库、官方书**早两周**访问。Fantasy Grounds 的对比页也确认 DDB 现在是"browser and mobile reading, character tools and the **browser-based Maps VTT**"。

→ **含义**：头部在把"车卡"变成"入口"，真正收费的是内容 + 跑团场地。**我们不该跟它拼平台**，应该拼"我们这套自制规则的正确性与易用性"——这是 DDB 永远做不了的（它没有战技/程序/灵能师）。

### 3.4 AI：已经进"跑团"和"内容生成"，但**还没进主流车卡**

- Quest Portal 有 AI Assistant 与 AI 相关工作流（<https://www.questportal.com/>）；
- 出现专门的"AI DM"产品（如 The Endlessness，宣称"full 5e rules engine"跑团）；
- 开源侧出现 AI 生成 5e 内容（items/NPC/characters/roll tables）的项目（<https://github.com/ByteProductions/Bytes-AI-Foundry>）。
- **但我没有找到 DDB / Roll20 / Foundry 官方把"AI 车卡"作为主推功能的证据**（DDB 侧页面被拦，无法证伪；按"未见即不写"处理）。**"AI 车卡"目前更像营销话术，不是成熟功能——标【未核实/未见】**。

### 3.5 纸质复兴与"反订阅"情绪

- MPMB（PDF）与 Fast Character（单页）都强调 **no ads / no subscription / no internet connection required**；
- Aurora 停更后仍有用户在用（Lemmy 帖），说明**"离线 + 免费 + 我自己掌控数据"**有真实需求；
- Demiplane 论坛里反复出现"想离开 DDB，但没人能替代"的表述。

→ **含义**：我们"无登录、无后端、localStorage、JSON 导入导出"不是缺点，而是**可以正面宣传的定位**——只要把易用性补上。

## ⑥ 给我们的结论：哪些能抄、哪些抄不了

### 6.1 「单页无账号静态网页」**完全能做到**（且已被别人证明）

| 能力 | 证据（别人已经这么做） |
|---|---|
| 单页分区 + 实时角色卡预览 | **nine\|tail**（<https://ninetail.org/charBuilder.html>）：左侧分区、右侧实时 AC/HP/豁免/技能 |
| 一张表单 + 留空随机 + 秒出角色 | **Fast Character**（<https://fastcharacter.com/>）：纯 HTML 表单，无账号 |
| 随机生成 + 逐字段重掷 | **Tetra-cube**（<https://tetra-cube.com/dnd/dnd-char-gen.html>）：GitHub Pages 静态站 |
| 分步向导 + 内联规则解释 + 选择校验 | 逻辑全在前端；Roll20 的做法给了交互范式 |
| 数值可审计（点开看算式） | Dicecloud 的设计哲学；纯前端可复刻 |
| 自动保存 / 多存档 | localStorage 已具备，加"存档槽 + 导入导出"即可 |
| 打印友好 / PDF | MPMB 证明"纸卡"是刚需；浏览器打印 CSS 即可 |
| 内容包导入（社区分发） | Plutonium 的「URL/文件/仓库」三源；Aurora 的「仓库 URL」 |
| 只读分享 | 把 state 压缩进 URL hash，或导出只读 HTML/图片（MPMB Flatten 的等价物） |

### 6.2 **必须有后端/账号**（或需要弱化承诺）

| 能力 | 为什么 | 我们的近似方案 |
|---|---|---|
| 跨设备云存档 | 需要账号 + 存储 | 导出/导入 JSON + "最近存档"提示；可选第三方网盘手动同步 |
| 队伍/战役、DM 查看全队 | 需要共享状态与服务端推送 | **共享码**：DM 发一个"允许内容清单 + 队伍码"的 JSON/URL，玩家导入；玩家导出只读卡给 DM |
| 内容共享（DDB 式 5 campaign） | 需要授权与账户体系 | 内容包 URL 索引（谁做了什么战技包） |
| 实时协作（Dicecloud/Quest Portal） | WebSocket / CRDT | 放弃，改为"导出→对方导入"的异步协作 |
| 版权内容分发（官方书） | 法律 | 不涉及：我们的规则是自制的，这是优势 |

### 6.3 三条最该立刻做的事（针对"相当难用"）

1. **11 步 → "3 步极速 + 11 步完整"双轨**，并在每步加"这步在选什么 / 影响哪些数值 / 可以先跳过"三行说明。（对标 DDB QuickStart + Roll20 内联解释）
2. **右侧卡从"展示"升级为"解释"**：改动项高亮 + 每个数字可点开看算式（对标 Dicecloud 的可审计性）。
3. **加"严格/自由"开关与明确的校验报错**（法术选多了、专长前置不满足、战技点数超了），并给"自动修正"按钮（对标 Roll20 的 validate + MPMB 的 FAQ 式边界说明）。
