# 5z 车卡器竞品调研与功能对比（2026-10-21）

> 调研人：DSH（Lead + 海外调研子代理）
> 对象：`5z-rules.top/car` 现有车卡器 vs 市面主流 D&D 5e 在线/离线车卡工具
> 配套文件：`2026-10-海外-5e车卡工具对比.md`（12+ 工具的逐项档案、证据等级、URL 清单）
> 本地实测产物：`5z_build/_shots/car-audit/`（截图 + report.json）、脚本 `5z_build/_test-car-audit.mjs`、`_test-car-mobile.mjs`

---

## 0. 摘要（TL;DR）

1. **你的车卡器不是「功能少」，而是「引导、校验、反馈」三类交互没做，外加几个可立刻修掉的硬伤。** 内容覆盖（1196 法术 / 804 专长 / 253 战技 / 233 程序 / 1585 魔法物品 / 58 种族 / 15 职业）在同类里属于第一梯队，且战技/程序/灵能师/赛博格是 5z 独有，市面工具无一覆盖。
2. **实测硬伤**：① 专长页 804 条一次性渲染，页面高 122,405px（手机 187,644px），没有分页；② 步骤条把「序号在前」显示成「已完成」，未选种族也能直接「下一步」，能一路做出 HP 0 / AC 9 的残卡且照样导出；③ 第 8–11 步刷新会被弹回第 7 步（存档 `load()` 把 step 钳到 ≤7）；④ 手机端实时预览被埋在文档 8,646px 处，首屏约一半被头部/横幅/步骤条占据；⑤ 1 级角色可以静默选 2 环法术，种族属性加值要玩家自己手填。
3. **市场格局（2026-10）**：海外只有 **D&D Beyond 一家在「官方内容 + 规则自动化车卡」上真正成熟**，且已转向「车卡=入口、内容+场地收费」的平台（Maps/Sigil/Encounters，免费账号限 6 角色）；**Demiplane 官方 2025-12 亲口承认「目前没有 5e 车卡器」**（Roll20 于 2024-06 收购 Demiplane，5e 车卡由 Roll20 承接，但用户抱怨「脱离桌面就难升级」）；Foundry 是自动化天花板但需自托管；MPMB 是最强 PDF 自动化但 SRD-only、只支持桌面 Acrobat；Aurora 已事实停更。
4. **中文生态里最该对标的不是 DDB，而是 `DND 车卡大师`**（GitHub: `BrandAgna/DND-Card-Master-Releases`，v1.9.86，免费离线的 Windows/Android 工具）：13 步向导、5E 2014 / 5R 2024 双规则、一键随机、逐级升级、逐行起始装备、导出 Word/Excel/JSON/ZIP、独立「看卡器」、按来源标注官方/第三方内容。**它证明「中文 + 分步 + 校验 + 导 Word」这套组合就是当前中文 5e 车卡的体验标杆。** 中文网页侧还有跑团 IO 人物卡、trpg-assistant、OBR 卡牌站等轻量尝试（都是「卡片管理」或实验性引导，没有一家把规则校验+导出做完整）；5etools 中文镜像（Kiwee / 不全书）、纯美苹果园、QQ 群骰子（屠龙骰等）承担「查资料 + 保存 + 掷骰」，玩家实际车卡仍以 Word/Excel 模板 + 资料站 + 群机器人为主。
5. **结论**：不需要跟 DDB 拼平台，也不要再堆内容。把「新手能走通、老手能快、数值可信」三件事补上，就能从「相当难用」变成「中文 5z 玩家唯一正确入口」。路线图见第 7 节：P0 五件事（专长页重构 / 步骤守卫与恢复 / 校验引擎 / 移动端 / 种族属性自动化）都不大，且大量复用已有的 Picker 组件与数据。

## 2. 我们现在有什么：实测盘点

### 2.1 流程与能力清单

11 步向导（顶部步骤条任意跳转）+ 右侧实时角色卡 + 底部「上一步/下一步」：

| 步骤 | 数据/选项 | 关键交互 | 校验 |
|---|---|---|---|
| 1 种族 | 58 个，按 12 个生物类型分类，搜索 | 卡片选择；详情含全部特性；人类「训练」6 选 1；部分种族亚种 chips（硬编码 12 个中英映射 + 自由输入） | 无（可跳过） |
| 2 职业 | 15 个（含赛博格、灵能师、召唤师等） | 卡片 + 职业表 + 特性全文 + 子职下拉（含嵌套子职） | 无 |

| 4 背景 | 5z 为开放式自定义 | 纯文本：名称/特性/语言/年龄/性别/阵营/信仰/身高体重/随身物品 | 无 |
| 5 技能 | 17 项技能，无/熟练/专精三档 | 配额 = 职业熟练数 + 背景 2 + 智力额外；✓ 标记职业可选池 | 固定职业熟练项硬拦截；配额超选只标红 |
| 6 专长 | 804 个，7 大类 | 搜索 + 分类下拉 + 选择/移除 + 已选面板；额外专长数手填 | 超配额 toast 拦截；**无先决条件/等级校验、无分页** |
| 7 法术 | 12 个职业法表（法师 453 个） | Picker：搜索 / 环位 chips / 学派 chips / 80 条一页 / 详情 / 选择 / 准备（准备施法者） | 准备数量超限 toast；**已知法术数量不校验、环阶不校验**（1 级可选 2 环） |
| 8 战技 | 253 个，5 流派 + 散人 | Picker 100 条/页、级别/类型 chips、流派选择、已选面板 | 无配额、无「流派入门专长」校验 |
| 9 程序 | 233 个，赛博格专属，按协议分层 | 协议切换 + Picker + 已选面板 | 职业门槛有（非赛博格直接提示跳过）；程序数量无校验 |
| 10 角色卡 | 全派生卡面 | 姓名/玩家/立绘（URL 或上传 ≤2MB）/备注；打印；导出 Word/Excel；派生值自动 | 无完整性检查 |
| 11 购物 | 1585 件魔法物品 | 预算手输、同调/神器/价格档/精确价格区间/45+ 分类 chips、80 条一页、已购合计 | 超预算只标红不阻断；**无常规装备/武器/护甲、无起始金币/装备包** |

## 3. 「相当难用」到底难在哪（根因分析）

用一句话概括：**这是一个「懂规则的人能凑合用的编辑器」，而不是「不懂规则也能走完的车卡器」。**

1. **不知道该做什么（导航/完成度）**：11 步全部可点、没有必填/选填标记、步骤条的「完成」只是序号在前。数据量大（804 专长、1585 物品）却没有"只显示我需要选的"的过滤。
2. **该自动的没自动（自动化缺口）**：种族/亚种属性加值、种族语言与训练带来的技能、装备/护甲/盾牌→AC、武器→攻击加值、起始金币与装备包——这些 DDB、Roll20、DND 车卡大师都自动，我们却让玩家自己算、自己填、甚至没有入口。玩家花在「查规则/算数」上的时间，比「做角色」还多。
3. **该拦的没拦（校验）**：未选种族能下一步；1 级能选 2 环法术；战技没有流派门槛；专长先决条件只显示不校验；导出不检查完整性。**后果不是"少填一项"，而是"做完才发现不合规"**，返工成本极高。
4. **该解释的没解释（可审计性）**：右侧预览只给结果不给算式；法术/专长/战技详情是纯文本，没有「为什么我不能选」「这个 +2 从哪来」。Dicecloud 的核心卖点就是每个数字可追到来源，我们完全没做。
5. **反馈与恢复**：没有保存提示、没有草稿列表、刷新回退、没有撤销；错误只有一闪而过的 toast。
6. **移动端与产出**：手机用户占相当比例，但头部 chrome 吃掉半屏、预览在底部、宽表溢出；导出的 Word 缺装备/攻击/AC 来源，DM 拿到还得补。

## 4. 市面工具盘点（精编）

> 完整 12+ 工具逐项档案、证据等级与 URL 见配套文件 `2026-10-海外-5e车卡工具对比.md`。这里只保留与「我们该怎么做」有关的信息。

### 4.1 海外：官方/商业

**D&D Beyond（官方，赛道基准）**
- 形态：账号云 + 网页/App；内容商店 + 车卡器 + 数字卡 + VTT 综合体。
- 流程：**双轨**——QuickStart 几分钟出 1 级角色；Standard 分步向导（section 可跳转可回退）；另有预生成角色。
- 亮点：全派生值自动、规则校验、内容共享（Master 最多 5 campaign）、Maps/Sigil VTT、订阅者内容库；免费账号限 6 角色。
- 短板：信息过载（StartPlaying 原文「卡面在线和打印都难读难导航」）、电子书另买、homebrew 无基础职业编辑器、付费墙高。
- 可借鉴：**双入口（快速/完整）**、section 化可跳转、把内容量做成「持续更新」价值。

**Roll20 Charactermancer**
- 形态：免费 VTT + 内容购买；可脱离房间独立建卡（Roll20 Characters）。
- 流程：**7 步向导**：种族 → 职业 → 属性（点数/掷骰，实时显示加值影响）→ 背景 → 装备 → 法术 → 专长；另有 NPC 生成器和直接改卡。
- 亮点：官方原话「每屏内联规则解释」「选择即写入卡、可反复换选对比」「向导内按 5e 规则校验」；**「直接改卡无校验」被明确写出来**——严格/自由两档心智清晰。
- 短板：不能打印（StartPlaying 点名）；升级被绑在会话流程里（Demiplane 论坛用户原话「difficult to update and level unless you on the tabletop with a session」）；个别选项提示了却没给（背景属性加值）。
- 可借鉴：**内联解释 + 选择即对比 + 严格/自由双模式**。

**Foundry VTT + dnd5e**
- 形态：自托管 VTT，$50 一次性买断；规则系统免费，官方模块另买。
- 亮点：自动化天花板——`automatic character advancement`（升级只问这一级新增选择）、Active Effects、Ruletips（名词悬浮解释）、队伍 actor、Requested Rolls；DDB Importer/Plutonium 可导入 DDB/5e.tools 内容（Importer 需 DDB cookie，README 自陈等于交密码）。
- 短板：自托管门槛高、触屏一般、无云存档、学习曲线陡。
- 可借鉴：**升级=增量提问**、**Ruletips**、**内容包 URL/文件/仓库三源导入**。

**Fantasy Grounds**：本体免费 + Character Vault/Character Wizard；**可自建职业**（DDB 不行）；买书收费。可借鉴「DM 共享源」：DM 给允许清单，玩家只能选这些——静态站可用一段 JSON/URL 参数近似。

**Demiplane**：**没有 5e 车卡器**（官方员工 2025-12 原话，用户被指引去 Roll20；2023 年承诺至今跳票，2026-07 仍有人追问无回复）。Roll20 于 2024-06-04 收购 Demiplane。**反面教材：不要把 roadmap 当卖点**。

**Hero Lab Online**：**无 D&D 授权**（官方 FAQ 原文）→ 5e 车卡实际不存在。

### 4.3 中文生态

**DND 车卡大师（最直接的对标，务必研究）**
- 入口：<https://github.com/BrandAgna/DND-Card-Master-Releases>（二进制发布仓库，v1.9.86；机核作者文章 <https://www.gcores.com/articles/216872>）。
- 形态：**免费、离线**、Windows EXE（37.3 MB）/ Android；本地起服务自动开浏览器；无账号无内购；中英双语（v1.9.86 新增）。
- 流程：**13 步**：规则（5E 2014 / 5R 2024 + 来源勾选）→ 基本信息（含头像/立绘）→ 等级（1–20，可拆多职业）→ 种族/物种 → 职业（主职/子职/兼职，主属性门槛校验）→ 背景（技能/工具/语言/起源专长/属性加值）→ 属性（购点/标准数组/4d6/**智能分配**+合法性实时校验）→ 技能（配额如「牧师 2/2」，种族/背景已给的自动锁定不占名额）→ **逐级升级**（每级 HP 平均/掷骰、特性原文、属性提升/换专长）→ 能力选择（法术/战技/祈唤/超魔/武器精通等集中一页，标配额，可一键随机填满，子职赠送法术单独标注）→ 装备（**职业起始装备逐行 A/B**、具体武器/法器、DM 额外金币，实时算起始金币）→ 概览（全部最终数值 + 待办）→ 导出。
- 产出：**ZIP 角色包**（完整卡 .docx 含规则原文 + .xlsx 多分页速查 + .carddy.json 存档 + 说明）、单项导出；独立「**看卡器**」：HP/临时 HP/短长休、先攻与回合、武器攻击一键掷骰、法术位/生命骰/职业资源打格、专注/力竭/激励/死亡豁免/金币/战斗备注。
- 质量：README 列 597 单测 + 42 前端 + 85 冒烟 + 129 Web + 5,461 随机角色 fuzz；未完成项**阻止继续查看或导出**（「未选定具体物品时，程序会阻止继续查看或导出」）。
- 短板：本地 EXE（无网页版、无跨设备）、无源码/未开源、规则库是官方+第三方（非自制规则）、无多人协作。
- **对比结论：交互与工程化明显领先我们；内容「5z 特色」我们领先。**

**资料站与社区路径**（2026-10-21 二次核实，详见附录 C）
- **5etools 中文镜像**：Kiwee（<https://5e.kiwee.top>，含 5e 2024、开源 `tjliqy/5etools-cn`、只有属性生成器 statgen 没有完整车卡）、不全书（<https://5echm.kagangtuya.top>，HTML 整合阅读器，2026-10 仍在更新）、英文原站 <https://5e.tools>；`5etools.wayneh.tw` 实测只剩 "Hello world"（已失效）。中文镜像生态高度分散（另有多份自托管镜像），**「玩家最常用哪个」无公开数据，不编比例**；这些站只解决「查」，不解决「建」。
- **纯美苹果园**（<https://www.goddessfantasy.net/bbs/index.php>）：中文 D&D 论坛/资料集散地，Word/Excel 角色卡模板的主要流传地；项目此前调研过「社区范例卡 92% 是 Word」（内部知识库记录）。新人车卡问答帖可检索到（部分版块需登录）。
- **跑团 IO（paotuan.io）**（<https://www.paotuan.io/> / 人物卡后台 <https://www.paotuan.io/admin/card.html>）：QQ/频道骰娘 + 网页后台；**人物卡支持文本或 Excel 导入**、属性/技能编辑、模板（可写 `3d6*5` 随机）、DND 卡自动识别豁免/技能熟练并算加值。本质是**卡片登记与管理**，不引导建卡。
- **TRPG 跑团助手（trpg-assistant）**（<https://github.com/LalyareMel/trpg-assistant>）：Next.js 网页应用，DND 5E 卡「六属性/HP/AC/先攻/速度/豁免/技能自动计算 + JSON 导入导出 + localStorage」，但为**表单式管理**，无种族/职业/专长选择与合法性校验；GitHub 数据显示 2025-10 后已停更（1 star）。
- **OBR 卡牌站**（<https://obr.dnd.center/card/>）：标题「DND 角色卡 · 单机版」，meta 描述「左侧角色卡，右侧规则资料，在卡片提示下查阅、选择并完成你的冒险者」——**有引导式建卡 UI**，但属于枭熊2 Full Suite 插件生态，无独立文档；是否做规则合法性校验/导出**未核实**。
- **QQ 群骰子/机器人**：如屠龙骰 DNDDicer（<https://h-elden.github.io/nonebot-plugin-dnddicer/guide/character-card>）用 `$属性$/$武器$` 文本角色卡，群里 `.力量检定` 自动代入加值；文档明确「购点是纸面计算，插件不参与」——机器人是「跑团中」工具，不是「建卡时」工具。
- **骰声 Dicecho**（<https://www.dicecho.com/>）：TRPG 模组库 + 测评 + 讨论区 + REPLAY，**负向核实：无角色卡入口**（`/zh/character` 404，导航仅模组/讨论区/视频/反馈）；价值是曝光渠道，不是车卡竞品。

### 4.4 三条赛道结论

1. **通用 5e 车卡赛道**：DDB 一家独大且平台化；Roll20/Demiplane 整合中、5e 车卡难产；Foundry 是发烧友自动化；轻量工具（Fast Character / nine|tail / Tetra-cube）证明**纯静态、无账号、单页实时卡完全可行**。
2. **中文赛道**：专用车卡软件只有 `DND 车卡大师` 一个像样的选手（且是离线 EXE），网页端只有实验性尝试（OBR 卡牌站的引导卡、跑团 IO/trpg-assistant 的角色卡管理），**没有人把「网页车卡 → 规则校验 → Word 导出」做完整**；玩家主流仍是「Word/Excel 模板 + 5etools 资料 + QQ 骰子」。
3. **自制规则赛道**：**没有强势玩家**。DDB/车卡大师都做不了 5z 的战技/程序/灵能/赛博格；这正是我们的位置。

## 6. 差距分析

### 6.1 我们领先/独有的（必须守住）

1. **5z 自制规则覆盖**：战技、程序、灵能师、赛博格、灵能武士、召唤师……市面没有任何工具能做；这是 DDB 永远补不上的。
2. **中文 + 与规则书同步**：数据从 CHM 自动解析，规则改版即同步；DND 车卡大师是人工维护的官方规则。
3. **Word 导出贴合社区习惯**：项目既有调研显示社区范例卡 92% 是 Word；这是 DDB/Roll20 都没有的「导出即用」。
4. **无账号、无后端、数据自持**：隐私与「站点永远免费」的定位，是 MPMB/Fast Character 用户同样看重的价值。
5. **数据接口**：`assets/card-data/*.json` 已被 QQ 骰子侧复用——「网页车卡 → 骰子机器人跑团」是别人没有的闭环潜力。

### 6.2 明显落后（按「对难用的边际收益」排序）

1. **引导双轨 + 完成度**（新手被 11 步吓退，老手想跳过）
2. **校验与报错**（做错不拦、做完才返工）
3. **种族/属性/装备自动化**（玩家手算规则，工具没帮上忙）
4. **专长页导航**（804 条一次性渲染）
5. **升级流程**（车高等级角色只能手填，且法术/专长选择不随等级变化）
6. **移动端**（首屏 chrome、预览在底部、宽表溢出）
7. **可审计性/内联解释**（不知道数字从哪来）
8. **打印/PDF/只读分享**（DM 查看仍靠传 Word）
9. **存档健壮性**（刷新回退、无版本迁移）
10. **帮助/教程/已知限制**（且顶着「测试版半成品」）

### 6.3 不必追（避免被带偏）

- 账号云存档、跨设备同步：需要后端与隐私责任，和「静态免费站」定位冲突（可用导出/导入 + URL 分享近似）。
- VTT/地图/战役管理：DDB/Roll20/Foundry 的战场，不是我们的。
- 官方内容商店/授权：我们做自制规则，不受版权限制，反而自由。
- 3D 骰子/AI DM：赛道未成熟，投入产出比低。

### 6.4 中文/私设环境的特有约束（别人没有的坑）

1. **规则书会频繁改版**（1.49→1.50→1.63）：存档必须带 `rulesVersion` 并在加载时体检（法术/专长改名、职业数据变化），否则「升级即丢卡」——MPMB/Aurora 都在这上面翻过车。
2. **Word 是社区标准产物**：导出质量 = 产品口碑；角色卡缺装备/攻击/AC 会让 Word 导出价值大打折扣。
3. **QQ 群是真实使用场景**：角色卡能被骰子机器人直接读（现有 `card-data` 同源），比「在线卡」更贴近玩家。
4. **玩家分布**：桌面 + 手机 + 群里截图/传文件并存；「打印/图片/Word」三种形态都要顺。

## 7. 改造路线图

> 原则：**不新增内容，只改交互**；优先复用现有 `Picker` 组件、`card-data` 数据与 Word 导出；每项都给出验收标准，便于后续 agent 实现后自动回归。

### 7.1 P0：立刻做（目标 1–2 周，直接扭转「难用」）

**P0-1 专长页重构（最高 ROI，改动最小）**
- 做法：把 `renderFeats()` 换成 `Picker`（与法术页同款）：分页 60–80 条/页、分类 chips（已有 7 类）、搜索、**先决条件单独一行 + "仅显示当前可选"过滤器**、已选面板吸顶；默认排序改为「1 级可选 → 职业相关 → 其他」，或按类别分组。
- 复用：`picker.js` 现成的 chips/分页/详情；`DATA.feats` 已有 `category` 与 `text`（含先决条件行）。
- 验收：DOM 条目 ≤80；页面高度 <9,000px；找「游龙流及门弟子」≤2 次操作；已选面板始终可见。

**P0-2 步骤守卫 + 完成度 + 恢复修复**
- 做法：① 修复 `car.js:126` 的 `Math.min(7,…)` → `Math.min(11,…)`；② 为每步定义 `required`（种族/职业/属性合法/技能满/专长满/法术满…），步骤条显示「必填/选填/已完成（✓）/未完成（!）」而非序号在前；③ 「下一步」在必填未完成时给明确提示（高亮缺失项 + 「仍要继续」二次确认，保留自由模式）；④ 角色卡步显示「待补清单」；⑤ 导出前统一校验。
- 验收：未选种族点下一步出现提示并高亮；第 11 步刷新仍停在第 11 步；导出前有完整性检查。

**P0-3 校验引擎（软提示 + 硬拦截可切换）**
- 做法：新增 `validate()` 汇总：法术按职业表配额（已知戏法/1 环数…）、准备上限、专长配额与先决条件（力量 15 等可解析的数值先行）、战技流派门槛、程序数量、购物预算、技能配额与职业可选池；输出 `{level:'error'|'warn', step, message, fix}`；UI 用「问题面板」而非 toast；提供「一键自动修正」。
- 验收：1 级选 2 环法术被拦/警告；未选种族不可导出（或强提示）；问题面板可定位到具体步骤。

**P0-4 移动端改造（CSS 为主）**
- 做法：头部压缩（标题+版本一行，导出按钮收进「⋯」菜单）、测试版横幅默认折叠、步骤条横向滚动（不换 3 行）、`#live` 改为底部浮动摘要（当前步相关 4–6 个数值）或可展开抽屉、角色卡表格加横向滚动容器/小屏卡片化、footer 保持 fixed。
- 验收：390×844 下首屏能看到步骤内容；实时数值始终可见；无横向溢出。

**P0-5 种族/属性自动化 + 点购硬约束**
- 做法：① 从 `race.traits` 解析「属性值加成：你的感知+2，敏捷+1」→ 结构化 `abilityBonuses`（解析失败则回退手填），`finalAttr` 计入种族加值；② 种族训练/亚种选择的技能熟练自动写入技能步（可取消）；③ 购点模式硬约束 8–16 且总点 ≤32（或明确「自由模式」开关）；④ 「手动调整」改名为「额外加值（专长/魔法物品等）」并折叠；⑤ 每个数字旁加 `?` 显示「基础 8 + 种族 2 + 升级 1 = 11」。
- 验收：选种族后对应「属性值加成」自动计入（如被遗忘者感知 +2、敏捷 +1），玩家无需手填；购点不能超 32；数字可展开算式。

### 7.2 P1：下一步（1–2 月）

| 项 | 要点 | 复用/依赖 |
|---|---|---|
| **装备与 AC/攻击** | 接入常规装备（武器/护甲/盾/法器）价格与 AC 公式；职业起始装备包 A/B 或起始金币；购物步合并常规+魔法物品；装备→AC/攻击加值/伤害自动进角色卡与 Word | 5z 装备页数据、`armorType/shield/armorBonus` 已存在但无 UI；`acValue()` 已支持多护甲类型 |

### 7.3 P2：以后（差异化/护城河）

1. **兼职/多职业**（pending 功能，结构改动大，建议在 P0 校验引擎稳定后做）。
2. **跑团模式 + 骰子机器人联动**：角色 JSON → QQ 群骰子可直接读（HP/法术位/检定加值），网页端做成「看卡器」；这是 DND 车卡大师有、我们没有、且我们数据同源最容易做的差异点。
3. **内容包生态**：社区自制战技/专长/程序包（JSON URL 索引），解决「804 专长里哪些是我们团能用的」。
4. **AI 辅助**：背景/姓名/立绘生成、自然语言改卡（「把力量改成 16」）；市场尚未成熟，最后做。
5. **账号/云存档**：不建议（违背无后端定位）；如要做，先做「只读分享 + 导出备份」。

### 7.4 如果只做三件事

1. **专长页分页/筛选**（1 天，收益最直观：「终于不用滚 12 万像素」）。
2. **步骤守卫 + 恢复修复 + 待补清单**（2–3 天，解决「做错不知道、刷新就丢」）。
3. **校验引擎（法术/专长/技能配额）+ 明确报错**（3–5 天，解决「做完才发现不合规」）。

做完这三件，再评估移动端（P0-4）与属性自动化（P0-5）。

## 8. 结论与定位建议

1. **不要试图成为「中文 DDB」**：DDB 的护城河是官方授权内容 + 平台；我们的护城河是 **5z 自制规则 + 中文 + 无账号免费 + Word/骰子生态**。
2. **本次「难用」的本质是「把规则判断外包给了玩家」**：种族加值、装备 AC、法术配额、专长前置、升级增量——只要这些交给工具，体验会立刻上一个台阶；内容再多也不会自动变好用。
3. **短期最有效的动作**不是加功能，而是：**专长页分页 + 步骤守卫/恢复 + 校验报错**（见 7.4），预计 1 周内就能让「难用」变成「能用」，再按 P1 补装备/升级/移动端。
4. **把「测试版（半成品）」的自我标签换掉**，配一页「3 分钟上手 + 已知限制 + 更新日志」；DND 车卡大师的信任感，很大一部分来自它把「能做什么、不能做什么」写清楚。
5. **保住独有优势**：Word 导出继续对齐社区空白卡；`card-data` 继续作为骰子机器人的单一数据源；规则改版时先做存档体检再发布。
